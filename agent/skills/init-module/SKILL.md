# init-module

모듈 루트를 프로젝트 지식 구조로 초기화하거나, 이미 초기화된 모듈의 지식 문서를 최신 상태로 갱신합니다.

## 인자

모듈 루트 경로를 인자로 받습니다. Claude Code/Codex 호출은 대부분 프로젝트 루트에서 이루어지므로, 스킬이 호출된 경로가 아니라 인자로 받은 경로를 모듈 루트로 사용합니다.

```
/init-module {모듈 루트 경로}
```

예시: `/init-module my-module` → 현재 작업 디렉토리(보통 프로젝트 루트) 기준 `./my-module`을 모듈 루트로 초기화합니다.

- 인자가 없으면 현재 디렉토리를 모듈 루트로 사용합니다.
- 인자로 받은 경로가 존재하지 않으면 새 모듈 생성으로 간주하고 디렉토리를 만든 뒤 최초 초기화를 진행합니다.

## 목적

인자로 받은 모듈 루트를 아래와 같은 구조로 초기화합니다.

```
{모듈 루트}/
  CLAUDE.md
  AGENTS.md
  agent/
    docs/
      README.md
      {지식 문서}.md
    skills/
  src/
```

Agent 락인을 지양하기 위해 실제 프로젝트 지식은 `docs/` 아래에 두고, `CLAUDE.md`/`AGENTS.md`는 그 문서로 라우팅하는 역할만 합니다. 모듈의 실제 작업 파일(소스 코드, 문서/콘텐츠, 설정 등)은 `src/`에 둡니다. 샘플은 [assets/module-template](./assets/module-template/)에 있습니다.

## 지식 문서 구조

- `docs/README.md`는 라우팅 전용 인덱스 문서입니다. 지식 본문을 직접 담지 않고, 템플릿 구조(문서 사용 원칙 + 문서 목록)를 유지합니다.
- 실제 지식은 `docs/` 아래 별도 문서로 작성합니다. 최초에는 `overview.md` 하나로 시작하고, 주제가 커지면 `architecture.md`, `conventions.md` 등으로 분리합니다.
- 지식 문서를 추가/변경하면 `README.md`의 문서 목록에 반드시 등록합니다. 각 항목은 문서 설명이 아니라 "어떤 상황에서 이 문서를 참고해야 하는지"가 드러나도록 작성합니다.

## src/ 분석 기준

지식 문서(최초 작성과 갱신 모두)는 `src/`의 실제 파일을 읽고 확인한 내용만으로 작성합니다. 추측하거나 일반론으로 채우지 않으며, 해당 사항이 없는 항목은 생략합니다.

모듈의 작업 유형은 코드에 한정되지 않습니다. 먼저 `src/`의 내용을 보고 이 모듈이 코드 모듈인지, 문서/콘텐츠 모듈인지, 혼합인지 파악한 뒤 해당하는 항목을 문서화합니다.

### 공통 항목

1. 모듈의 목적과 범위: 이 모듈이 무엇을 만드는지, 프로젝트 안에서 어떤 역할인지.
2. 디렉토리 구조: `src/` 내부 구조와 각 부분의 역할.
3. 컨벤션: 작업물에서 반복적으로 관찰되는 패턴과 규칙(단발성 사례는 제외).
4. 주의사항과 제약: 작업 시 반드시 알아야 할 함정, 전제 조건.

### 코드 모듈 항목

1. 기술 스택과 주요 의존성: 언어, 프레임워크, 핵심 라이브러리.
2. 명령어: 빌드, 테스트, 실행, 린트 등 실제로 동작이 확인되는 명령(`package.json` scripts, Makefile 등 근거 파일 기준).
3. 아키텍처와 주요 흐름: 진입점, 핵심 데이터/제어 흐름, 모듈 간 의존 관계.

### 문서/콘텐츠 모듈 항목

1. 산출물의 종류와 독자: 어떤 문서/콘텐츠를 누구를 대상으로 작성하는지.
2. 작성 규칙: 문체, 톤, 용어, 포맷 등 작성물에서 확인되는 규칙.
3. 문서 간 관계: 문서들의 구성 체계, 참조/링크 구조, 작성 순서가 있다면 그 흐름.
4. 빌드/배포 방식: 정적 사이트 생성, 변환 스크립트 등 산출물을 만들어내는 도구와 명령(있는 경우).

혼합 모듈은 두 항목군을 모두 적용합니다.

## 초기화/갱신 여부 판단

이 스킬은 최초 1회만이 아니라 반복 호출될 수 있습니다. 매번 아래 두 가지를 각각 점검하고, 해당하는 작업만 수행합니다.

### 구조 점검 (요소별)

구조 전체를 있음/없음으로 판단하지 않고, 템플릿의 각 요소를 개별적으로 확인해 부족한 것만 보충합니다.

| 요소 | 없을 때 |
|------|---------|
| `CLAUDE.md` | 템플릿 샘플로 생성 |
| `AGENTS.md` | 템플릿 샘플로 생성 |
| `docs/README.md` | 템플릿 샘플로 생성 |
| `agent/skills/` | 빈 디렉토리로 생성 |
| `src/` | 빈 디렉토리로 생성 |

모든 요소가 없으면 최초 초기화로 간주합니다. 이미 있는 요소는 덮어쓰지 않습니다(`CLAUDE.md`/`AGENTS.md`의 정리는 아래 이관 절차에서 다룹니다).

작업 파일(소스 코드, 문서/콘텐츠 등)이 `src/` 밖에 이미 존재하는 경우, 임의로 `src/`로 이동하지 않습니다. 파일 위치는 그대로 두고 지식 문서에는 실제 위치를 기준으로 작성하며, 완료 보고에서 구조가 템플릿과 다르다는 점을 사용자에게 알립니다.

### 지식 문서 갱신 필요 여부 (git 기준)

`docs/`의 지식 문서는 `src/`를 분석한 결과물이므로, `src/`가 변경되면 낡을 수 있습니다. git 이력으로 판단합니다(명령은 모듈 루트 기준 경로 사용).

```bash
# docs를 마지막으로 커밋한 시점
DOCS_LAST=$(git log -1 --format=%H -- {모듈 루트}/docs)

# 그 이후 src/에 커밋된 변경
git log --oneline "$DOCS_LAST"..HEAD -- {모듈 루트}/src

# 커밋되지 않은 src/ 변경
git status --porcelain -- {모듈 루트}/src
```

- `DOCS_LAST`가 비어 있으면(지식 문서가 커밋된 적 없음): `src/`에 파일이 있으면 지식 문서를 작성/갱신합니다.
- 위 두 명령 중 하나라도 출력이 있으면: 갱신이 필요합니다.
- 둘 다 비어 있으면: 지식 문서는 최신 상태입니다.
- git으로 판단하기 어려운 경우(예: `docs`에 커밋되지 않은 수정이 있는 경우): `src/` 내용과 지식 문서를 직접 대조해 판단합니다.

## 절차

1. 구조 보충: 위 구조 점검 기준에 따라 템플릿의 각 요소 중 없는 것을 생성합니다.
2. 지식 문서 작성/갱신: 갱신 필요 여부 판단 결과에 따라 수행합니다.
   - 최초 작성: `src/`를 위 분석 기준대로 분석해 `docs/overview.md`(필요 시 추가 문서)를 작성하고, `README.md` 문서 목록에 등록합니다.
   - 갱신: 동일한 분석을 다시 수행해 기존 지식 문서 중 낡은 부분은 갱신하고, 여전히 유효한 부분은 유지합니다. 문서를 추가/삭제했다면 `README.md` 문서 목록도 함께 갱신합니다.
3. 이관 대상 구분: `CLAUDE.md` 또는 `AGENTS.md`에 템플릿 라우팅 문구 이외의 내용이 남아 있다면, 프로젝트 지식과 에이전트 specific한 내용(해당 에이전트에서만 의미가 있는 설정/훅/지시문 등)을 구분합니다.
   - 프로젝트 지식에 해당하는 내용: `docs/`의 적절한 지식 문서로 이관합니다(기존 내용 유지 + 추가). 맞는 문서가 없으면 새 문서를 만들고 `README.md` 문서 목록에 등록합니다.
   - 에이전트 specific한 내용: 이관하지 않고 원래 파일에 남겨둡니다.
4. `CLAUDE.md`/`AGENTS.md` 정리: [assets/module-template](./assets/module-template/)의 샘플을 기준으로 정리합니다. 3번에서 이관한 프로젝트 지식은 제거하되, 남겨두기로 한 에이전트 specific한 내용은 유지합니다. 라우팅 문구 이외에 남길 내용이 없다면 샘플로 그대로 생성(또는 대체)합니다.
5. 완료 보고: 아래 형식으로 수행 결과를 사용자에게 보고합니다.

## 완료 보고

작업을 마치면 다음을 요약해 보고합니다.

- 판정 결과: 최초 초기화 / 구조 보충 / 지식 문서 갱신 / 이관 / 변경 없음 중 해당하는 것.
- 생성한 파일과 디렉토리 목록.
- 갱신한 지식 문서와 갱신 이유(반영한 `src/` 변경 내용 요약).
- 이관한 내용 요약과 `CLAUDE.md`/`AGENTS.md`에 남긴 에이전트 specific한 내용.
- 템플릿 구조와 다른 점이 있다면 그 내용(예: `src/` 밖에 있는 작업 파일).

아무 작업이 필요 없었던 경우에도 "이미 최신 상태이므로 변경 사항 없음"을 명시적으로 보고합니다.
