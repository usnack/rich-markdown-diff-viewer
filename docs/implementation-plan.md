# Rich Markdown Diff — 구현 계획

작성일: 2026-10-21

## 1. 문서 목적과 작업 지시

새로운 프로젝트에서 macOS용 마크다운 Git diff 뷰어를 처음부터 구현하기 위한 독립적인 요구사항 및 개발 계획이다. 아래 확정 요구사항은 사용자 인터뷰를 거쳐 승인됐다. 같은 질문을 다시 반복하지 말고 구현을 진행한다. 기술 구성과 세부 알고리즘은 제안이며, 요구사항을 충족하는 범위에서 변경할 수 있다.

이 문서 작성의 범위는 계획 전달이다. 새 프로젝트 생성 및 실제 재구현은 이 문서를 전달받은 새 작업에서 진행한다. 기존 프로젝트와 동일한 디렉터리에 동시에 작업하지 않는다.

## 2. 사용 배경과 목표

- 사용자는 macOS에서 Orca로 마크다운 문서를 작성한다.
- Orca의 raw diff만으로는 렌더링된 문서의 변경을 검토하기 어렵다.
- GitHub PR의 rich diff와 유사하게 제목, 본문, 목록, 표 등의 서식을 유지한 채 변경을 확인하고 싶다.
- Orca 옆에 별도 앱을 열어 두고, 파일을 저장하면 변경 내용이 자동으로 갱신되는 흐름이다.
- 통합형과 좌우형 비교를 모두 제공한다.
- 앱은 읽기 전용이다. 문서 편집과 Git 변경 작업은 기존 도구에서 수행한다.

## 3. 확정 요구사항

### 3.1 앱과 저장소

- macOS에서 실행하는 별도 데스크톱 앱.
- 사용자가 로컬 Git 저장소 폴더를 선택한다.
- 왼쪽 사이드바에 변경된 마크다운 파일을 표시하고, 선택한 파일의 diff를 본문에 표시한다.
- Git에 아직 추가하지 않은 새 마크다운 파일도 포함한다. 단, Git ignore 대상은 제외한다.
- 마지막으로 연 저장소와 선택 파일을 기억한다.
- Orca 내부 뷰를 변경하거나 Orca 플러그인을 개발하는 범위는 아니다.

### 3.2 비교 기준

| UI 선택 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 전체 변경 — 기본값 | HEAD | 현재 작업 디렉터리 |
| 스테이징 전 변경 | 인덱스 | 현재 작업 디렉터리 |
| 스테이징된 변경 | HEAD | 인덱스 |

- 새 파일은 전체 변경 및 스테이징 전 변경에서 추가로 표시한다.
- 스테이징된 변경에는 인덱스에 반영된 파일만 표시한다.
- HEAD가 없는 초기 저장소는 빈 기준 문서로 처리한다.
- 파일 추가, 삭제, 이름 변경, 일부만 스테이징된 파일을 구분한다.
- 커밋끼리·브랜치끼리 비교하는 UI는 첫 버전 범위에서 제외한다.

### 3.3 비교 화면

- 통합형: 하나의 문서 흐름 안에서 삭제는 빨강, 추가는 초록으로 표시한다.
- 좌우형: 같은 창의 왼쪽에 변경 전, 오른쪽에 변경 후를 표시한다.
- 좌우형의 대응 블록을 나란히 정렬하고, 두 문서를 동기화해 스크롤한다.
- 독립 스크롤 및 동기화 해제 버튼은 필요하지 않다.
- 문서 전체를 기본으로 표시한다.
- ‘변경 부분만 보기’와 이전·다음 변경 이동 버튼을 제공한다.
- 문장 전체가 아니라 실제 바뀐 문구를 세밀하게 강조한다.
- 제목 수준, 굵게, 링크 등 서식만 바뀐 경우에도 변경임을 표시한다.
- 표는 가능한 한 셀 내부의 변경 문구를 강조한다.
- 색상만으로 구분하지 않도록 추가·삭제·서식 변경 표시도 함께 제공한다.

### 3.4 렌더링

- 제목, 본문, 강조, 링크, 중첩 목록, 체크박스, 표, 인용, 코드 블록, 이미지.
- Mermaid 다이어그램.
- 문서용 HTML: details, summary, table, div, img 등과 접기·펼치기.
- 문서에 포함된 스타일은 앱 UI에 영향을 주지 않도록 격리한다.
- 사용자 문서의 JavaScript 및 iframe은 실행하지 않는다.
- 수식 렌더링은 필수 요구사항으로 확정되지 않았으며 첫 버전 범위에 넣지 않는다.

### 3.5 Mermaid 및 이미지 비교

- 변경된 Mermaid는 전·후를 각각 렌더링한다. 도형 내부에 문구 diff를 강제로 삽입하지 않는다.
- 통합형에서는 전·후 다이어그램을 위아래로, 좌우형에서는 나란히 표시한다.
- Mermaid 소스 diff를 펼쳐 볼 수 있다.
- 문법 오류가 있더라도 나머지 문서는 표시하고 해당 블록에 오류와 원문을 제공한다.
- 로컬 이미지와 외부 URL 이미지를 모두 표시한다.
- 로컬 이미지는 가능한 경우 비교 대상 시점의 파일을 사용한다. HEAD는 HEAD의 이미지, 인덱스는 인덱스의 이미지, 작업 디렉터리는 현재 이미지를 읽는다.
- 과거 이미지를 찾지 못하면 명시적인 누락 표시를 한다. 현재 이미지를 과거 이미지인 것처럼 표시하지 않는다.
- 외부 이미지는 현재 URL의 응답을 표시한다. 외부 이미지의 과거 모습은 복원할 수 없다.

### 3.6 자동 갱신과 상태 유지

- Orca에서 파일을 저장하면 diff를 자동 갱신한다.
- 갱신 전 읽던 위치를 최대한 유지하고 새 변경으로 자동 이동하지 않는다.
- 자동 갱신 일시정지 및 재개 버튼을 제공한다.
- 저장소·파일 선택, 비교 기준, 화면 모드 변경을 명확히 구분한다.
- 변경 파일이 없거나 선택 파일이 사라졌을 때 적절한 빈 상태를 표시한다.

## 4. 제안 기술 구성

macOS 전용이므로 Swift 기반 앱 셸과 WKWebView 기반 문서 렌더러 구성을 기본안으로 한다. 사용자 요구사항은 기술 스택 자체를 강제하지 않는다.

| 계층 | 역할 | 제안 |
| --- | --- | --- |
| 네이티브 앱 | 창, 폴더 선택, 상태 저장 | Swift + AppKit 또는 SwiftUI |
| Git 서비스 | 비교 대상 조회, 파일 목록, 이미지 읽기 | Git CLI를 인자 배열로 실행 |
| 문서 모델 | 파싱, 블록 정렬, 문구 및 서식 diff | TypeScript + Markdown AST |
| 렌더러 | 통합·좌우 모드, HTML, Mermaid | WKWebView + 번들된 JS/CSS |
| 갱신 서비스 | 파일·인덱스·HEAD 변경 감지 | 파일 감시 + debounce + 보완 재조회 |
| 검증 | 엔진, Git 통합, 실제 앱 동작 | 단위 테스트 + 임시 저장소 + macOS UI 검증 |

- Markdown 파서, diff 엔진, HTML sanitizer, Mermaid는 구현 시 공식 문서와 라이선스를 확인하고 버전을 고정한다.
- 런타임 CDN 의존성을 두지 않고 렌더링 라이브러리를 앱에 포함한다.
- 최종 사용자가 Node나 Python 프로세스를 별도로 실행하지 않아도 앱을 열 수 있어야 한다.
- 개발 단계에서 Node와 빌드 도구를 사용하는 것은 허용한다.
- 외부 URL 이미지를 제외한 일반 문서와 Mermaid는 오프라인에서도 표시한다.

## 5. 핵심 설계

### 5.1 Git 조회

1. 저장소 루트와 실제 Git 디렉터리를 해석한다. worktree의 `.git` 파일도 처리한다.
2. 선택한 비교 기준에 해당하는 파일 목록과 상태를 가져온다.
3. 경로의 공백, 한글, 개행을 안전하게 다루도록 NUL 구분 출력을 사용한다.
4. 전·후 파일 경로를 각각 보존해 이름 변경 및 상대 이미지 경로를 처리한다.
5. 전체 문서 원문을 읽어 렌더링한다. Git patch 텍스트만으로 문서를 재구성하지 않는다.
6. 저장소 읽기는 비동기로 실행하고 오류·시간 초과를 UI에 전달한다.

Git 명령은 셸 문자열 연결 대신 인자 배열로 실행한다. 문서에서 넘어온 값으로 임의 명령을 실행할 수 없도록 네이티브 브리지를 제한한다. 바이너리나 읽을 수 없는 인코딩은 조용히 잘라내지 않고 설명을 표시한다.

### 5.2 블록 및 문구 diff

1. 원문 위치를 보존하는 AST로 문서를 파싱한다.
2. 제목, 문단, 목록, 표, 코드, HTML, Mermaid 등을 비교 단위로 분류한다.
3. 동일 블록을 우선 연결하고, 그 사이에서 유형과 텍스트 유사도를 이용해 수정 블록을 연결한다.
4. 대응한 텍스트 블록에는 문구 단위 diff를 적용한다. 한국어와 유니코드 문자를 손상시키지 않는다.
5. 텍스트가 같더라도 노드 유형, 속성, 링크 대상 등이 다르면 서식 변경으로 표시한다.
6. 표의 행·열 구조가 유지되면 셀 단위로 비교한다. 구조 변경이 크면 전·후 표와 변경 표시를 제공한다.
7. 복잡한 HTML은 억지로 DOM을 섞지 않고 전·후 렌더링 및 원문 diff로 대체한다.

Markdown 원문에 diff 태그를 끼워 넣어 다시 파싱하는 방식을 피한다. 문서 구조를 만든 뒤 텍스트 노드에 강조를 적용해 표·목록·링크 구조가 깨지지 않게 한다. 참조형 링크 정의 변경도 해당 링크의 변경으로 드러나야 한다.

### 5.3 화면 모델과 스크롤

- 전·후 블록 ID, 변경 종류, 원문 위치, 렌더링 데이터를 하나의 비교 모델로 관리한다.
- 통합형과 좌우형은 같은 비교 모델을 사용한다.
- 좌우형은 공유 스크롤 컨테이너와 대응 블록별 행을 우선 검토한다. 각 행 높이는 양쪽 중 큰 높이에 맞춘다.
- 이미지 로드, Mermaid 렌더링, details 토글, 창 크기 변경 후 높이를 재계산한다.
- 자동 갱신 전에 상단 가시 블록과 그 내부 오프셋을 저장하고 갱신 후 복원한다.
- 기준 블록이 삭제되면 가장 가까운 유지 블록으로 복원한다.
- ‘변경 부분만 보기’는 AST와 목록·표 구조를 손상시키지 않는 블록 단위로 처리한다.

### 5.4 HTML·이미지 경계

- HTML sanitizer로 script, 이벤트 핸들러, iframe, 위험 URL을 제거한다.
- 문서 CSS를 허용할 경우 격리 컨테이너와 CSS 필터링을 함께 사용한다. 격리만으로 네트워크 접근까지 막힌다고 가정하지 않는다.
- 문서의 스타일이 사이드바·툴바·다른 비교 영역을 덮지 않도록 한다.
- 로컬 이미지 경로는 문서 경로 기준으로 정규화하고 저장소 외부 접근과 심볼릭 링크 우회를 차단한다.
- 외부 링크를 클릭하면 명시적인 사용자 동작에 따라 기본 브라우저로 연다.
- 사용자 문서가 네이티브 브리지 API에 접근하지 못하도록 한다.

### 5.5 갱신 경쟁 상태

- 파일 저장 이벤트를 묶어서 처리한다. 초기 debounce 값은 300ms 정도로 두고 실제 동작으로 조정한다.
- 파일 내용뿐 아니라 스테이징, 커밋, 체크아웃으로 인한 기준 변경도 감지한다.
- 요청마다 저장소·파일·비교 기준·세대 번호를 붙여 오래된 응답이 최신 화면을 덮지 못하게 한다.
- 갱신 일시정지 중에는 화면을 유지하고, 재개 시 최신 상태를 다시 읽는다.

## 7. 구현 순서와 단계별 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1. 앱 골격 | 새 프로젝트, 앱 창, 폴더 선택, 웹 리소스 번들 | macOS에서 앱을 실행하고 저장소 선택 가능 |
| 2. Git 데이터 | 세 비교 기준, 파일 목록, 원문 읽기 | 임시 저장소에서 staged/unstaged/untracked 결과가 실제 Git 상태와 일치 |
| 3. 일반 문서 diff | AST, 블록 정렬, 문구·서식 변경 | 한글 문장, 목록, 표, 서식만 바뀐 문서를 정확히 비교 |
| 4. 비교 UI | 통합·좌우, 전체·변경만, 변경 이동 | 같은 diff 모델로 모든 보기 전환이 동작 |
| 5. 확장 렌더링 | HTML 격리, Mermaid, 이미지 | 전·후 렌더링, 소스 펼치기, 오류 격리 및 이미지 시점 검증 |
| 6. 작업 흐름 | 자동 갱신, 일시정지, 위치·선택 기억 | Orca 저장 후 갱신, 읽던 위치 유지, 재시작 복원 |
| 7. 배포 및 검증 | 앱 패키징, 실제 화면 확인, 실행 안내 | 깨끗한 빌드에서 재현 가능하고 전체 수용 기준 충족 |

각 단계가 끝날 때 구현 완료와 검증 완료를 구분해 보고한다. 빌드 파일이 있다는 이유만으로 전체 완료로 보고하지 않는다.

## 8. 검증 시나리오

### Git 통합

- HEAD 없는 저장소, 변경 없음, 신규 파일, 삭제, 이름 변경.
- 동일 파일의 staged 변경과 unstaged 변경을 각각 구분.
- 한글·공백이 포함된 파일명, 중첩 폴더, Git worktree.
- ignore 대상 제외, 저장소 외부 심볼릭 링크 차단.
- HEAD·인덱스·현재 파일에 서로 다른 로컬 이미지를 두고 시점별 표시 확인.

### 문서 비교

- 한글 문장 일부 추가·삭제·교체, 이모지와 조합 문자.
- 제목 수준·강조·링크 주소만 변경, 참조형 링크 정의 변경.
- 중첩 목록, 체크박스, 코드 블록, 표 셀 및 행·열 추가·삭제.
- Mermaid 정상·변경·문법 오류, HTML details와 문서 스타일.
- 이미지 경로 변경·누락·외부 이미지 로드 실패.
- 공백만 바뀌어 렌더링이 같더라도 원문 변경 사실은 표시.

### 실제 macOS 앱

- 저장소 열기 → 파일 선택 → 세 비교 기준 전환.
- 통합형 ↔ 좌우형, 변경만 보기, 이전·다음 이동.
- 긴 문서 중간에서 수정·저장했을 때 위치 유지.
- 이미지 및 Mermaid 로드 후에도 좌우 대응 유지.
- 자동 갱신 일시정지·재개, 앱 종료·재실행 시 선택 복원.
- 파일을 빠르게 연속 선택했을 때 이전 응답이 현재 파일 화면을 덮지 않음.
- 렌더러 오류가 다른 파일 열기나 앱 조작을 막지 않음.

보안 경계는 script·이벤트 속성·위험 링크·외부 파일 경로 예제로 확인한다. 검증에는 별도 데모 저장소를 사용한다.

## 9. 최종 수용 기준 및 산출물

- [ ] 사용자가 macOS 앱을 직접 열고 로컬 Git 저장소를 선택할 수 있다.
- [ ] 세 비교 기준과 새 파일 처리가 정확하다.
- [ ] 통합형과 좌우형 모두 rich text로 읽을 수 있다.
- [ ] 문구 변경 및 서식 변경이 표시된다.
- [ ] 좌우 블록 정렬과 동기화 스크롤이 동작한다.
- [ ] Mermaid와 문서용 HTML이 지원된다.
- [ ] 이미지의 비교 시점과 누락 상태가 구분된다.
- [ ] 자동 갱신·일시정지·읽던 위치 유지가 동작한다.
- [ ] 저장소와 선택 파일을 재시작 후 복원한다.
- [ ] 실제 앱 화면으로 핵심 시나리오를 검증했다.
- [ ] 소스, 실행 가능한 앱, 빌드·실행 안내, 테스트 명령, 알려진 제한을 제공한다.

개인 로컬 실행용 패키지와 외부 배포용 서명·공증은 구분한다. 외부 배포용 인증서나 공증이 필요한 경우 별도 작업으로 설명한다.

## 10. 새 구현 에이전트에게 전달할 시작 프롬프트

> 이 문서를 기준으로 새 프로젝트에서 macOS용 Rich Markdown Diff 앱을 구현해줘. 확정 요구사항은 인터뷰와 승인이 끝난 상태이므로 같은 질문을 반복하지 말고 진행해. 기술 구성은 제안이므로 필요하면 이유를 설명하고 조정해도 돼. 기존 프로젝트와 분리된 디렉터리에서 작업하고, Git 조회부터 rich diff, Mermaid·HTML, 자동 갱신까지 단계적으로 완성해. 실제 macOS 앱의 화면 동작을 검증한 뒤 소스와 실행 가능한 앱, 실행 안내, 검증 결과와 남은 제한을 제공해. 실행하지 못한 검증을 통과했다고 보고하지 마.
